# GUARD-13: npm-токен не пойман в prompt пользователя

**Статус:** обновлено 2026-11-25 (вечер) — подтвердился второй, настоящий дефект:
prompt-хук умирает после перезагрузки плагина в долгоживущем сервисе
**Дата:** 2026-11-25

## Симптом

Пользователь вставил в чат вывод PowerShell об ошибке выполнения команды
с npm-токеном (`npm_…`). В модели текст пришёл частично: строка команды
обрывалась на `npm_` + 16 символов с «...», маска guard'а не появилась.
Пользователь: «токен не целый, странно что guard не поймал утечку».
Запрос: «добавить шаблон npm по аналогии с sk».

## Root cause (итог, два независимых слоя)

**Слой 1 — обрывок в оригинальном сообщении (не дефект guard'а).**
В первой вставке полного токена в чате никогда не было: PowerShell при
показе ошибки обрезает длинную строку команды («...» без закрывающей
кавычки). До guard'а дошёл `npm_` + 16 символов — ниже порога паттерна
{20,}. Ловить произвольно обрезанные секреты нельзя в принципе.

**Слой 2 — реальный дефект рантайма (подтверждён канарейками).**
Синтетический полный токен (npm_ + 36 alnum), вставленный пользователем
в prompt дважды (с кавычками и без), дошёл до модели **незамаскированным**,
prompt-записей в audit нет. При этом:

- код загруженной копии содержит и prompt-хук, и npm-паттерн (CHK-13);
- prompt-хук **работал** в текущем процессе сразу после его старта
  (CHK-11) и перестал обрабатываться после перезагрузки плагина тем же
  процессом (CHK-12);
- tool- и context-слои после перезагрузки продолжают работать (CHK-9).

Вывод: долгоживущий сервис opencode 2.4.0 при повторной инициализации
плагина (новая location/session boot) теряет session-хук "prompt",
не логируя ошибку регистрации. После `opencode service restart` хук
должен восстановиться (проверка канарейкой обязательна). Дополнительно
рантайм сидит на устаревшей кэш-копии 1.2.1 (CHK-10) — opencode кэширует
резолв npm `@latest` и не перекачивает новые версии, пока кэш-каталог
существует.

Рекомендации: `opencode service restart`; очистка кэш-каталога плагина;
после публикации 1.2.4 — пин версии в opencode.json вместо `@latest`;
обновление opencode до 2.4.1 (вышла 24.11, могла исправить re-boot хуков).

## Тупики (T1..T7)

- **T1 — гипотеза «паттерна нет в коде».** Опровергнуто: `git log -S
  npm-token` показывает первый коммит 9622265; паттерн в
  `src/patterns.ts` (строка 48). Добавлять нечего.
- **T2 — «regex не матчит даже синтетический токен».** Первый probe
  выдал 0 совпадений — артефакт моего тестового скрипта: после сбоя
  PowerShell-квотинга однострочник был переписан в файл, а `matchAll`
  после вызова `.test()` на том же глобальном regex получал сдвинутый
  `lastIndex`. Чистая репродукция даёт 1 совпадение во всех стилях (CHK-3).
- **T3 — гипотеза «stale lastIndex в кэше скомпилированных паттернов
  приводит к пропускам».** Опровергнуто: `src/scan.ts` перед каждым
  циклом сканирования явно сбрасывает `re.lastIndex = 0` (строка 83).
- **T4 — гипотеза «prompt-хук вообще не работает в рантайме».**
  Частично подтвердилась позже (CHK-8..12): хук мёртв не «вообще», а
  после перезагрузки плагина; до перезагрузки работал (CHK-11).
- **T5 — гипотеза «prompt-хук выключен опцией scanPrompts».**
  Опровергнуто: дефолт `true` с первого коммита (`config.ts:98`,
  `scanPrompts: o.scanPrompts !== false`), в конфиге пользователя опция
  не задана.
- **T6 — «pickaxe `git log -S` не находит `hook("prompt")`/`kind: "context"`
  в истории».** Артефакт PowerShell-квотинга: PS удаляет внутренние
  двойные кавычки при передаче аргументов native-командам, и git искал
  строку без кавычек. Перепроверено через `git show` + Select-String —
  строки в истории есть (6892ea8).
- **T7 — гипотеза «рантайм исполняет код из репозитория» (по записям
  kind=context с 12 ноября).** Опровергнуто сервер-логом: entrypoint
  текущего процесса — кэш-копия npm (CHK-10); записи с 12 ноября
  объясняются более ранним источником загрузки (локальный каталог
  `C:/pojects/AI_Projects/opencode-guard`, старое имя проекта).

## Чекпоинты (CHK-1..14)

- **CHK-1**: паттерн `npm-token` присутствует в `src/patterns.ts` с
  первого коммита (подтверждено `git log -S`, чтение файла).
- **CHK-2**: prompt-скраб существует в коде HEAD: `src/guard.ts:516`,
  хук мутирует `event.prompt.text` (подтверждено чтением).
- **CHK-3**: синтетический токен npm_ + 36 alnum матчится паттерном:
  fresh `matchAll` с флагами gd = 1, g = 1, scan-style exec после
  сброса lastIndex = 1 (репродукционный скрипт, boolean-факты).
- **CHK-4**: `src/scan.ts` сбрасывает `lastIndex` перед сканом (строка 83).
- **CHK-5**: audit `guard-audit.jsonl` (1460 записей): kind prompt — 13
  за всю историю; 25 ноября — 29 записей, prompt-kind = 0, context-kind
  с api-key = 0. Запись в момент вставки токена отсутствует.
- **CHK-6**: текст, дошедший до модели, содержит `npm_` + ровно 16
  символов и «...» без закрывающей кавычки — ниже порога {20,};
  16-символьный обрывок синтетики матчей не даёт (проверено тем же
  скриптом: partial_16char_matches = 0).
- **CHK-7**: рантайм-экземпляр guard'а жив и мутирует контент — в ходе
  расследования записанный скрипт был замаскирован на лету (ключевое
  слово apiKey со знаком присваивания — известный GUARD-12 FP,
  неоткаченная версия паттернов в рантайме; подтверждает факт
  «tool-хуки активны»).
- **CHK-8**: канарейка №1 и №2 (синтетический npm_ + 36 alnum,
  пользовательская вставка в TUI, с кавычками и без) дошли до модели
  незамаскированными; prompt-записей в audit в эти моменты нет.
- **CHK-9**: диапазоны audit-kinds: kind=prompt — 13 записей, только
  2026-11-13 → 2026-11-23T20:20Z; kind=context — непрерывно
  2026-11-12 → 2026-11-25 (последняя 06:07Z); tool.before/after — живы
  по сей день. Слои context/tool активны, prompt — нет.
- **CHK-10**: сервер-лог: текущий процесс run=e245db93 стартовал
  2026-11-23T12:55:08Z как opencode **2.4.0** (serve --service); плагин
  загружен из кэша `opencode-v2-guard@latest/1794851860941` — это
  версия **1.2.1** (копия от 2026-11-16), НЕ 1.2.3 из реестра.
- **CHK-11**: последняя prompt-запись audit (2026-11-23T20:20:19Z)
  сделана ВНУТРИ текущего процесса (старт 12:55Z того же дня) —
  prompt-хук работал после старта сервиса на opencode 2.4.0.
- **CHK-12**: сервер-лог фиксирует повторные загрузки плагина тем же
  процессом: 2026-11-24T19:41:30Z и 2026-11-25T05:07:04Z («location
  services booted» + «loading plugin»). После них prompt-записей нет,
  канарейки не маскируются — хук теряется при re-boot плагина.
- **CHK-13**: fingerprint загруженной копии 1.2.1 (TS-источник, который
  исполняет Bun): содержит `hook("prompt"`, `kind: "context"`, паттерн
  `npm_[A-Za-z0-9]{20,}` в patterns.ts → коду плагина есть чем ловить
  канарейку; отсутствие маски — не отсутствие паттерна.
- **CHK-14**: документация V2 API (opencode.ai/docs/build/plugins/server)
  содержит хук prompt-admission с мутацией `event.prompt.text`; synthetic/
  shell-сообщения хук не проходят, обычные TUI-промпты — проходят.
  В логе: «OpenCode update available 2.4.0 → 2.4.1» (24.11).
- **CHK-15**: живая репродукция через `opencode run` (тот же сервис,
  новая сессия → штатный prompt-admission): канарейка дошла до модели
  и вернулась в ответе **посимвольно совпадающей** с исходной
  (exact_raw=true, masked=false). Из трёх прогонов два дали
  однозначный raw, один — неопределённый (модель исказила эхо).
  Плюс две TUI-канарейки в основной сессии — итого 4 независимых
  подтверждения. Баг воспроизводим по требованию.
- **CHK-16**: сервер-лог: единственный запуск serve после
  2026-11-23T12:55Z — текущий run e245db93 (2.4.0). Других процессов
  в «окне смерти» хука не было: хук работал (audit 23.11 20:20Z) и
  умер **внутри одного процесса** без рестарта.
- **CHK-17**: release notes v2.4.0: плагин с **голым именем** (как в
  конфиге пользователя) не авто-обновляется вовсе; `name@latest` и

- **CHK-18**: release notes v2.4.1 (23.11 15:57Z) не содержат исправлений

  бага нет (скан «plugin prompt hook», первая страница выдачи) —
  баг, по-видимому, не заявлен апстриму.
- **CHK-19**: управляемая песочница (второй serve на порту 28999,
  отдельный каталог, тот же плагин из кэша 1.2.1, DEBUG-лог).
  Открытие: `location_idle_timeout: "45s"` отклоняется нормализацией

- **CHK-20**: свежий процесс песочницы пережил ≥5 циклов

  пропусков нет. Одно- и многократные re-boot'ы хук НЕ убивают —

- **CHK-23**: инструментарий отлова перехода: часовой канарейкой-автомат

  (порт 28999, DEBUG-лог). Скрипт дважды независимо ревьюирован

  исправлены — culture-баг `[datetime]::Parse` (UTC+3 растягивал окно
  до ~3ч) заменён на `[datetimeoffset]::Parse().UtcDateTime`; добавлены
  таймаут процесса, liveness-проверки, enum result+streak.
  Существенная находка ревью №2: `opencode run` с токеном в argv пишет
  его в общий лог (`cli starting args=...`) на каждом прогоне;
  митигировано подачей промпта через stdin. E2E-прогон: result=OK,
  masked=true, audit_prompt=true, дельта npm_ в общем логе = 0.
- **CHK-24**: после диффа ревью №2 (streak не сбрасывается на
  error-путях; enum сокращён до договорного) скрипт финально одобрен
  обоими ревьюерами (parse_errors=0, повторный e2e: OK). Автоматизация
  `guard13-canary-hourly` (id aut_211dbbfd6001Hl3St76qaJ6ORx) активна:
  каждый час, expires 2026-11-26T12:00+03:00; статус — построчно в
  `canary-status.jsonl` (result/streak; HOOK_DEAD-greppable). Песочный
  serve (порт 28999) работает с DEBUG-логом. Цель: поймать момент
  смерти prompt-хука в долгоживущем процессе с полным DEBUG-логом окна.
- **Ревизия корневой причины (T8)**: гипотеза «prompt-хук умирает при
  re-boot плагина» опровергнута экспериментом CHK-20 как достаточная
  причина. Уточнение: смерть хука наблюдается только в долгоживущем
  (≈2 суток) процессе `serve --service`; кандидатные факторы — uptime/
  накопленное состояние процесса, режим супервизии --service,
  перемежение boot'ов множества location'ов (в песочнице был один).
  Архитектурная зацепка из v2.4.0: PluginHooks — per-location node
  (packages/core/src/plugin/hooks.ts, `makeLocationNode`), prompt-admission
  предоставляет location-сервисы сессии (session.ts, `instances.provide`);
  tool-хуки в сломанном процессе живы при мёртвом prompt — узкое место
  надо искать в рассинхронизации этих путей при старении процесса.

## Артефакты и очистка

- Баг-репорт в opencode: https://github.com/anomalyco/opencode/issues/66299
  (опубликован 2026-11-25, согласован с владельцем).
- Временные скрипты `g13*.mjs` в `%TEMP%\opencode` — удалены после
  фиксации фактов.
- Секретов в журнале нет: токены упоминаются только как «npm_ + длина»,
  значения не печатались. Канарейка — синтетическая строка, реальный
  токен отозван/ротирован пользователем.
- Опциональное ужесточение паттерна (снизить порог {20,}) не
  рекомендуется: рост FP, а обрезанные секреты в общем случае
  ненадёжно детектируемы.
- План восстановления защиты prompt'ов:
  1) `opencode service restart`;
  2) повторить канарейку (npm_ + 36 alnum) — ожидаем маску api-key;
  3) очистить `%USERPROFILE%\.cache\opencode\npm\opencode-v2-guard@latest`
     и после публикации 1.2.4 запиновать версию в opencode.json;
  4) рассмотреть обновление opencode до 2.4.1.
- Идея на будущее (GUARD-14?): страховка на случай повторной потери
  session-хука — например, периодическая самопроверка регистрации
  prompt-хука с записью факта в audit, чтобы пропажа была видна в логе.
