# Журнал расследования GUARD-9: секрет на wire при audit "redacted"

> Правило ведения см. в AGENTS.md («Журнал расследований»). Каждый тупик и
> чекпоинт фиксируются сразу после того, как они обнаружены.

Контекст: v1.2.1, инцидент 2026-11-17T19:00:42Z (сессия ses_e1858985effeFjGHtCht7w13aF):
audit плагина сообщил `prompt credential redacted`, но модель получила raw-ключ
(assistant-ответ эхом вывел секрет). Среда воспроизведения:
`C:\Users\admin\AppData\Local\Temp\opencode\guard-repro\` (изолированные
XDG_CONFIG_HOME/XDG_DATA_HOME, mock OpenAI-compatible провайдер на 127.0.0.1:8123,
canary — фиктивный, 41 символ «guardtest»+32 hex, в canary.txt; значение не печатается).

## Root cause (двухчастный; runtime v2.2.5)

**Часть A — инцидентная (триггер на v2.2.5 не воспроизведён, трактуется как
структурный разрыв).** Подпись форензики инцидента:

- audit `prompt redacted count=1` в 19:00:42.681Z, user-сообщение персистено
  в 19:00:42.702Z — **уже замаскированным** (0 фрагментов ≥8 символов в БД и
  на диске, включая кодированные формы);
- ассистентский эхо содержит raw len=58 ×2 — модель видела raw-ключ;
- context-аудита для этого turn'а нет — значит, копия, из которой собралось
  тело запроса, не проходила ни prompt-, ни context-слой;
- форма ключа в вставке: `$env:CAILA_API_KEY = "…"` (kv-форма) — паттерном
  матчится, маска видна пользователю после Enter. Голых вариантов в
  персистентности нет, поэтому инцидент — не «незаматченный вариант»
  (часть B), а **pre-mutation in-memory копия**: маска легла на копию, которая
  стала персистентностью, но тело запроса собрано из другой, более ранней
  копии.

**Часть B — воспроизведена на v2.2.5 (CHK-11/12).** Многострочная вставка с
одним значением в нескольких формах: kv-форма и Bearer-форма матчатся и
маскируются (audit `count=2 redacted`), а **голая** строка значения (без
`key=`-контекста) не матчится ни одним паттерном — персистентность и тело
запроса содержат raw при audit «redacted». Pattern-based wire scrub
(первый патч) этот класс не закрывает: на wire те же паттерны находят 0
совпадений.

**Закрытие (патч v1.2.2).** Wire-level scrub на `session.http.request`
(транспорт-независимый последний рубеж: любой запрос к модели проходит этот
хук до отправки байтов) усилен **реестром значений**: все admission-хуки
(prompt, context, tool.after, shell) запоминают raw-значения замаскированных
матчей (per-session, in-memory, TTL 6ч, cap 64/сессия; для kv-паттернов
`Match.raw` — это capture-группа, т.е. само значение без контекста — CHK-14).
Wire hook после pattern-скраба делает второй проход — literal replace по
запомненным значениям (включая JSON-escaped форму для вложенных JSON-строк),
маска всегда полная `<REDACTED:category>`. Это закрывает обе части: неважно,
как raw попал в тело — через незаматченный вариант (B) или через pre-mask
копию (A): если guard маскировал это значение в сессии, wire его заменит.
Подтверждение: CHK-13 (e2e на serve), CHK-15 (юнит + e2e регрессии).

## Тупики (что не работает и почему)

- **T1. Убийство процессов opencode «оптом»** — роняет собственную сессию
  агента. Останавливать только свои serve по PID/порту (проверяя командную
  строку процесса).
- **T2. Секреты, записанные в файлы через write/edit, маскируются средой**
  (sensitive-data-guard): синтетический секрет в исходнике теста/дебаг-скрипта
  превращается в `<REDACTED:api-key:…>` ещё на диске. Из-за этого первый прогон
  wire-scrub юнит-тестов был ложно-зелёным/ложно-красным («тело уже
  замаскировано до хука», `deepRedact n=0`). Правило: секретные строки
  собирать в рантайме (`["sk","live",…].join("-")`), в файле — только
  уже-замаскированные плейсхолдеры.
- **T3. queue в простаивающую сессию** — не воспроизводит утечку: guard-мутация
  доходит до wire (req-5, req-7 capture маскированы даже с выключенным
  config.policy). Утечка — только при busy tool-loop.
- **T4. Mock без проверки role:"tool"** — бесконечный tool-loop: каждый
  следующий запрос снова содержит триггер в last user text → вечные
  tool_calls → сессия busy вечно, serve приходится убивать. Скрипт tool-call
  должен отдавать tool_calls только пока в messages нет role:"tool".
- **T5. Плагин-проба молча не грузится**, если у него нет доступного
  `@opencode/plugin` (нет node_modules) — в логе serve ошибок нет. Ставить
  пакет в node_modules рядом (`npm.cmd install --prefix <dir> @opencode/plugin`).
- **T6. Опции плагинов применяются только при свежем serve** — долгоживущий
  сервис держит старые инстансы плагинов. Любая смена конфига = рестарт serve.
- **T7. `npm` из PowerShell** — execution policy блокирует npm.ps1; вызывать
  `npm.cmd`.
- **T8. Запросы API завёрнуты в `data`** — POST /api/session возвращает
  `{data:{id}}` (первая попытка чтения `id` без обёртки дала пустую сессию).
- **T12. `indexOf(canary)` с перезаписанной переменной** — в скрипте проверки
  capture переменная `canary` (строка) была затенена булевой `let canary =
  false`, и поиск шёл по подстроке «false» → ложный вывод «canary raw в
  req-8/req-10». Перепроверка: ни один capture с активным guard не содержит
  canary; единственный raw-на-wire — req-6 (policy off, guard отсутствует,
  queue в idle-сессию). CHK-4 в исходной формулировке отозван; механизм
  инцидента требует переустановки. Урок: не затенять искомое значение
  переменной результата; проверять и весь capture-файл, и поле body.
- **T13. Очередное сообщение при проверке персистентности** — живёт в таблице
  `session_inbox` (pending), а не `session_message`; «отсутствие canary в
  session_message» для ещё не промотированного сообщения — норма, а не признак
  bypass.
- **T9. Mismatch имён хуков в тестовом ctx** — регистрация под `http.request`,
  а `fire` ищет `session:http.request`: хук молча не вызывается, тест падает
  с «raw secret on wire». Регистрация и fire должны строить ключ одинаково
  (`"session:" + name` в обоих местах).
- **T10. Общий audit-файл между тестами** — ассерт «нет wire-события» в
  clean-body тесте ловит события предыдущих тестов. Уникальный audit-каталог
  на тест (`.tmp-audit-wire-<seq>`, в .gitignore).
- **T11. `sk-live-…` под контекстом `api_key = "…"` детектируется паттерном
  openai-key с частичной маской** (`<REDACTED:api-key:sk-…cdef>`, keepLast),
  а не `credential`. Ассерты на маску должны проверять отсутствие
  уникальной середины секрета + наличие любого плейсхолдера `<REDACTED:`.
- **T14. Прямой путь с точной инцидентной конфигурацией** (npm-пакет
  v1.2.1 из кэша + policy ON, не отключать `-opencode.config.policy`) —
  утечки нет: prompt-мутация доходит до context-вида и до wire (CHK-10).
  Инцидент не объясняется «прямым путём».
- **T15. Queue в busy tool-loop** (mock с tool-call по маркеру) — исходная
  гипотеза Root cause НЕ подтвердилась: queued-промпт промотируется на
  idle-границе, обрабатывается prompt-хуком и уходит маскированным
  (mock req-3 maskPresent=true). Гипотеза «инжекция pre-mutation копии в
  in-flight запросы» отозвана; исходный раздел Root cause переписан.
- **T16. Resume сессии с историей после рестарта serve** — утечки нет:
  контекст собирается из персистентных (маскированных) сообщений.
- **T17. Многострочная вставка (quoted + Bearer + bare)** — утечка
  воспроизведена, но причина иная, чем в исходной гипотезе: bare-вариант не
  матчится паттернами (CHK-11/12). Т.е. T17 — не подтверждение T15, а
  открытие части B root cause.
- **T18. Забытая интеграция value-скраба в wire hook** — процессный тупик:
  реестр значений был реализован (rememberValues на всех admission-хукax),
  serve12 прогнан — mock req-9 canaryPresent=true, wire-аудита нет. In-process
  debug-тест воспроизвёл провал: prompt-аудит писал count=1 (реестр заполнен),
  но wire hook вызывал только deepRedact — вызов deepScrubValues не был
  вставлен (правка прервалась). Урок: после добавления компонента проверять
  все точки его потребления; прогон через serve не заменяет юнит-проверку
  интеграции, а отсутствие записи в wire-аудите — диагностический сигнал
  «хук отработал вхолостую».

## Чекпоинты (подтверждённые факты)

- **CHK-1.** Нативный scrub (`opencode.config.policy`) покрывает прямой
  admission и queue в idle-сессию; capture req-6 (raw на wire) получен при
  policy OFF — т.е. факт «native scrub не покрывает X» подтверждён только для
  случая, когда policy выключена. Утверждение «policy не покрывает queue в
  busy-сессию» из исходной формулировки отозвано вместе с CHK-4 (T15).
- **CHK-2.** Guard prompt-hook: мутация доходит до persistence (persisted user
  message маскирован и в инциденте, и в тестах), audit пишет `redacted`.
- **CHK-3.** Guard-мутация доходит до wire в openai-compatible транспорте для
  путей idle-queue и busy-queue без tool-loop (в обеих конфигурациях — с
  policy on и off). «Prompt hook не доходит до wire» — неверная гипотеза.
- **CHK-4. ОТЗОВАН (T12).** Первоначальное «ключевое воспроизведение»
  (raw в capture req-8/req-10) — артефакт затенённой переменной в скрипте
  проверки. Инжекция pre-mutation копии в in-flight tool-loop на v2.2.5 не
  воспроизведена; механизм инцидента переустановлен (см. Root cause, часть A).
- **CHK-5.** Хук `session.http.request` срабатывает на runtime v2.2.5
  (kind=primary, content-type application/json, `request: Request` доступен,
  async-обработчики поддерживаются) — подтверждено probe-плагином
  (probe-events.jsonl).
- **CHK-6.** Патч реализован: `session.http.request` в src/guard.ts —
  clone→text→JSON.parse→deepRedact(mutate)→пересборка Request (content-length
  пересчитан), cap 8 МБ, warn-mode не переписывает, аудит `kind:context,
  detail:"wire"`. `npm run typecheck` и npm test (175) — зелёные.
- **CHK-7.** Юнит-тесты test/wire-scrub.test.ts (5 шт., секреты собираются в
  рантайме): маскирование тела на wire, покрытие string/assistant/array part
  схем, clean body байт-в-байт, warn mode не переписывает, non-JSON/GET
  игнорируются, аудит `detail:"wire"`. Все 5 зелёные. Первые прогоны были
  невалидны (T2, T9, T10).
- **CHK-8.** TODO: e2e-регрессия на реальном runtime (mock + busy tool-loop),
  которая падает на старом коде; проверка «на старом коде падает» через
  git stash патча.
- **CHK-9.** Probe на v2.2.5: `session.context` отдаёт сообщения в форме
  `{id, role, content: array, metadata}` (без parts); без guard canary доходит
  до провайдера raw на прямом пути (mock capture, policy on/off).
- **CHK-10.** Свежий serve + pattern-only wire патч + probe: prompt-мутация
  доходит до context-вида (canaryInEvent=false) и до wire (canaryInBody=false)
  на прямом пути; wire-записи в аудите нет (n=0) — прямой путь закрывался даже
  старым кодом.
- **CHK-11.** Инцидентная конфигурация (npm v1.2.1 + policy ON) + многострочная
  вставка (quoted + Bearer + bare): prompt count=2 (bare не матчится),
  персистентность содержит raw-вхождение (rawCanaryHits=1), canaryInContent=true,
  canaryInBody=true, mock req-7 canaryPresent=true — raw на wire при audit
  «redacted». Часть B root cause воспроизведена.
- **CHK-12.** Serve11 (первый патч: wire scrub ТОЛЬКО по паттернам), тот же
  сценарий: prompt count=2, wire-записи в аудите нет (паттерны не матчат голое
  вхождение), canaryInBody=true, mock req-8 canaryPresent=true — pattern-based
  wire scrub класс B не закрывает.
- **CHK-13.** Serve13 (реестр значений + value-scrub интегрирован в wire hook),
  тот же сценарий: prompt count=2 redacted, wire-аудит `detail:"wire"`
  action:"redacted", probe canaryInBody=false, mock req-10 canaryPresent=false
  maskPresent=true. **Класс B закрыт на реальном runtime.**
- **CHK-14.** Для kv-паттернов (`maskGroup: 1`) `Match.raw` — capture-группа,
  т.е. само значение секрета без контекста (src/scan.ts, collect():
  `const raw = m[group] ?? m[0]`). Реестр запоминает именно значение —
  вхождение в любом контексте/копии находится literal-поиском.
- **CHK-15.** Тесты: 183 юнит-теста зелёные (включая новые: bare wire
  occurrence скрабится по значению + escaped-форма во вложенном JSON; wire-аудит
  считает value-замены, не только паттерны); e2e с мульти-вариантным canary
  (kv + bare, очередь в busy tool-loop, реальный serve) — зелёный, wire-аудит
  =1, персистентность: kv-форма маскирована, bare персистится raw
  (документированное ограничение). Регрессионная ценность подтверждена
  фактически: на промежуточном коде (wire без реестра) debug-версия теста
  падала (T18), на финальном — зелёная. npm run typecheck зелёный.

## Артефакты и очистка

- capture-файлы и tool-output тестовых сессий содержат фиктивный canary —
  реальной компрометации нет, но каталоги `…\guard-repro\mock\capture\`,
  `…\guard-repro\guard-audit-*\`, probe-events.jsonl, serve*.txt/pid/out/err,
  временные XDG-каталоги guard-repro и canary.txt подлежат удалению после
  закрытия расследования. Форензика-скрипты секретов не содержат (canary
  читается из canary.txt в рантайме).
- Фоновые процессы: mock (PID 28180, порт 8123), serve13 (PID 19164, порт
  8236) — остановлены по PID с проверкой cmdline (правило T1).
- Реестр значений в рантайме держит raw-значения в памяти serve (TTL 6ч,
  cap 64/сессия, max 128 сессий) — не персистится и не логируется; в аудит
  пишутся только категории и счётчики.
