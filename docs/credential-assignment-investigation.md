# Расследование: credential-assignment портит присваивания ссылок на env (GUARD-12)

Статус: фикс ОТКАТЕН по решению мейнтейнера (2026-11-23) — выбран путь
инструкций для агентов вместо контекстного фикса; см. docs/masking-guide.md.
Журнал сохраняет факты (CHK-1..7) и тупики (T1..T4) для возможного возврата
к фиксу. Код в src/ восстановлен к HEAD; сам журнал чинился фрагментным
скриптом — старый runtime маскировал env-ref'ы и в этом документе при записи.

## Root cause

Паттерн `credential-assignment` (src/patterns.ts) захватывает «значение после
ключа» без семантики значения: `apiKey = process.env.OPENAI_API_KEY`
матчится, значение-ссылка маскируется `<REDACTED:credential>`, и на путях
записи (tool.execute.before → deepRedact, enforce) исходник заменяется
синтаксически битым кодом. Write возвращает success — порча молчаливая,
всплывает на компиляции.

Это тот же класс дефекта, что и «email в путях» (docs/pii-email-spec.md,
FR1): маска ломает синтаксический контекст. Тот фикс (`isPathContext` в
scan.ts) был сделан намеренно только для категории `pii` — комментарий
«secrets always stay masked»; credential-значения контекстной проверки не
получили. GUARD-12 добавляет credential-сайд аналог: validate-хук
`isCodeLikeValue` — не маскировать, когда значение синтаксически является
выражением-ссылкой (identifier-chain `process.env.X`, bracket-access
`env["X"]`, вызов геттера `getenv("X")` / `os.environ.get("X")`,
интерполяция `${...}`, shell-ссылка `$VAR`). Fail-closed: всё
нераспознанное маскируется как раньше.

В процессе фикса обнаружены два дополнительных зазора того же класса (T3, T4).

## Тупики (T1..T4)

- **T1. Allowlist «похоже на секрет» (префиксы/энтропия).** Отклонено: guard
  — контрол fail-closed; детектор секретности даёт false negative на
  нестандартные секреты (DSN, однострочные ключи), т.е. дырка в защите ради
  удобства.
- **T2. Audit-only + предупреждение для значений-ссылок.** Отклонено как
  основной вариант: подмена текста в warn-режиме и порча write остаются;
  годится только как доп. слой видимости.
- **T3 (тупик, найден тестами). Прямое подключение `validate: isCodeLikeValue`.
 ** Ожидал: true = «пропустить». Получил: в scan.ts collect() validate —
 acceptance-проверка (`if (p.validate && !p.validate(...)) continue`), true =
 «принять и маскировать». Семантика перевернулась: env-ссылки маскировались,
 литералы пропускались. Подтверждено probe-скриптом (validate attached,
 validate('hunter2')=false при n=0 в scan). Фикс: `validate: (raw) =>
 !isCodeLikeValue(raw)`.
- **T4 (тупик, найден тестами). Обрубание значения на кавычке.** После T3
  тесты показали: `token = process.env['GITHUB_TOKEN']` всё ещё маскируется.
  Причина: value-группа `([^\s'\"]{4,})` останавливается на `'`, raw =
  `process.env[` — обрубок без закрывающей скобки не распознаётся как код.
  Фикс: значение расширено до `((?:[^\s'\"]|'[^']*'|\"[^\"]*\"){4,})` —
  кавычные сегменты внутри значения разрешены; для литералов в кавычках
  поведение не изменилось (открывающая кавычка съедается `['\"]?`).
- **Уточнение: кавычный дискриминатор (по вопросу о dotted-литералах).**
  Дву-сегментные значения классифицировались как ссылки и пропускались.
  Дискриминатор: env-ссылка в коде почти всегда не закавычена (выражение,
  а не строка), «человеческий» пароль — почти всегда в кавычках. validate
  смотрит на символ перед спаном: кавычка → литерал → всегда маскировать;
  без кавычек → правило «похоже на код». Обратный шаблон в бэктиках
  (`token = <REDACTED:credential>.env.X}``) распознаётся отдельным правилом (strip + рекурсия).

## Чекпоинты

- CHK-1: legacy-паттерн (копия без validate, в тесте CHK-1) превращает
  `const apiKey = process.env.OPENAI_API_KEY` в
  `const apiKey = <REDACTED:credential>` — подтверждено тестом
  `CHK-1: pre-fix pattern (no validate) corrupts env references`.
- CHK-2: 7 тестов test/credential-assignment.test.ts зелёные: env-refs
  (JS/TS bracket/getter/интерполяция, Python os.environ/getenv, Deno, shell
  `$VAR`) не тронуты; литералы (в т.ч. голые идентификаторы) маскируются;
  специфичные паттерны (sk-) продолжают срабатывать на тех же строках.
- CHK-3: полный прогон — 193/193 pass, `tsc --noEmit` exit 0.
- CHK-4 (live, рантайм): guard, работающий в сессии на момент правки (старый
  код, сервис не перечитывает плагин), при записи тестового файла замаскировал
  env-ref присваивания прямо на диске — 23 `<REDACTED:*>` вхождения вместо
  исходника. Воспроизведена и сама молчаливая порча, и правило AGENTS.md о
  перезапуске serve. После переписывания теста с фрагментной сборкой строк
  (canary-правило) файл чист: единственный `<REDACTED:credential>` —
  намеренная константа MASK.
- CHK-5 (probe, булевы флаги): закавыченные dotted-литералы маскируются
  (`password = "Summer.Rain2024"`, `password = "Qwerty.Pass"`,
  `token: '<REDACTED:credential>'`, python-форма — masked=true); env-ref остаётся нетронутым
  (untouched=true). Не закавыченный dotted-литерал (YAML bare scalar,
  типичная форма .env) — masked=false, задокументирован как остаточный риск.
- CHK-6 (live, рантайм, повтор): при записи probe-скрипта тот же старый
  runtime замаскировал значения-интерполяции `${pw1}`/`${ref}` в шаблонных
  строках, оставив незакрытые литералы (битый JS на диске) — второе живое
  воспроизведение порчи; новый код интерполяции пропускает. Файл переписан
  фрагментной сборкой.
- CHK-7: набор credential-тестов 10/10 pass (включая кавычный дискриминатор),
  полный прогон и typecheck зелёные.

## Остаточный риск (осознанный, задокументированный)

- Закавыченные dotted-литералы маскируются (кавычный дискриминатор);
  остаточный риск — НЕзакавыченные значения (YAML bare scalar, типичная
  форма .env: `password: Summer.Rain2024` без кавычек) и короткие обрезанные
  JWT-подобные сегменты (<8 симв., не ловятся jwt-паттерном).
  Специфичные паттерны (sk-, ghp_, JWT, AWS) на такие значения не влияют и
  работают как раньше. Принято: ложные ссылки в коде на порядки вероятнее
  точечных dotted-литералов; усиление (энтропия/allowlist корневых
  неймспейсов) — кандидат на отдельный тикет.
- `${...}`-интерполяция и `$VAR` пропускаются целиком — значение не
  литерал-секрет по определению синтаксиса.

## Артефакты и очистка

- src/patterns.ts — `isCodeLikeValue` + validate-хук + расширенная value-группа.
- test/credential-assignment.test.ts — 10 тестов; все сматчимые строки
  собраны в рантайме из фрагментов (canary-правило AGENTS.md).
- Probe-скрипты во временной папке сессии (guard12-probe*.mjs, логи) — удалены.
- Требуется свежий `opencode serve` (перезапуск сессии), чтобы работающий
  guard подхватил исправленный код.
